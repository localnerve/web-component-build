# v3.5.0 — Syntax-aware template injection & multi-template support

## Problem

v3.4.x injected minified CSS/HTML/link markup into a component's JavaScript by
**raw text replacement** of a placeholder token (`String.prototype.replace`), with a
hand-rolled per-line backslash hack (`htmlText.replace(/$/mg, '\\')`) to turn newlines
into JS line continuations. That approach only worked while every injected fragment was
free of quotes (`'`, `"`, `` ` ``), `${` sequences, and backslashes — any of which in the
HTML or CSS would corrupt the surrounding JavaScript.

## Solution

Injection is now **syntax-aware**. See `lib/replace.js`:

1. The component's JS is parsed with [acorn](https://github.com/acornjs/acorn).
2. Each token is located inside its containing string or template literal (absolute
   offsets, so "token as a substring of a larger literal" still works).
3. The payload is escaped **for that literal's quote context**:
   - `'` / `"` — backslashes, the delimiter, and newlines are escaped (one-line interior)
   - `` ` `` — backticks, `${`, and backslashes are escaped; raw newlines stay
4. Splices are applied **back-to-front** so multiple tokens (across or within literals)
   never invalidate earlier offsets.

The per-line backslash hack is gone. The emitted JS is always valid regardless of the
markup's content, and downstream terser normalizes the formatting.

## New API (additive, non-breaking)

### `templates` option

A component may now carry **multiple** HTML templates (e.g. default / error / empty
states), each referenced by its own distinct token:

```js
const result = await build(outputDir, {
  jsPath: '/…/component.js',
  cssPath: '/…/component.css',        // shared, prepended to every template
  cssLinkHref: '//cdn/component.css',  // shared, prepended to every template
  templates: [
    { name: 'default', htmlPath: '/…/default.html', token: '__TPL_DEFAULT__' },
    { name: 'error',   htmlPath: '/…/error.html',   token: '__TPL_ERROR__' },
    { name: 'empty',   htmlPath: '/…/empty.html',   token: '__TPL_EMPTY__', cssLinkHref: '//cdn/other.css' }
  ]
});
```

Each entry:

- **name** `{String}` — output filename (`${name}.html`). Defaults to the input basename.
- **htmlPath** `{String}` — input html for this template (optional; a template may be
  css/link-only).
- **token** `{String|RegExp}` — the placeholder in the JS to replace.
- **cssLinkHref** `{String}` — optional per-template override of the shared link href.

### Backward compatibility

The flat single-template options (`htmlPath` + `jsReplacement`) still work unchanged and
are internally synthesized into a one-element template list. All v3.4.x callers are
unaffected; every pre-existing fixture passes unmodified on this branch.

## Result object

- Unchanged: `getCss()`, `cssPath`, `getJs()`, `jsPath`.
- **New:** `htmls` — an ordered array (matching `templates` input order) of
  `{ name, path, getHtml }`.
- Kept shorthands (resolve to the first html output): `getHtml()`, `htmlPath`.

## Output-filename collision fix

Previously every template's html would have been written to `outputDir/<basename>.html`,
so two templates with the same basename would silently overwrite each other. Output names
now come from each template's `name` (or its basename), and `build()` **throws** when two
templates resolve to the same output name, forcing distinct names.

## Errors

- Token not found in the JS → throws `Replacement token … not found in javascript source.`
- Token outside any string/template literal → throws.
- Token inside a template `${…}` expression or crossing an expression boundary → throws.
- Overlapping tokens → throws.
- Duplicate html output names → throws.
