# v4.0.0 — Breaking API changes on the syntax-aware core

v4 builds on the v3.5.0 syntax-aware injection core (`lib/replace.js`) and makes three
breaking changes to the public API. The injection engine itself is unchanged from 3.5.0.

## Breaking changes

### 1. `templates` is the only way to describe html/css/link

The flat single-template options **`htmlPath`** and **`jsReplacement`** are removed.
Passing either now throws a migration error:

```
v4 removed the flat "htmlPath"/"jsReplacement" options. Migrate to the "templates" array, e.g. templates: [{ name, htmlPath, token }].
```

`build()` accepts `options.templates` (an Array; default `[]`). A template entry:

- **name** `{String}` — output filename (`${name}.html`). Defaults to the input basename.
- **htmlPath** `{String}` — input html for this template (optional).
- **token** `{String|RegExp}` — the placeholder in the JS to replace.
- **cssPath** `{String}` — optional per-template css override (falls back to shared `cssPath`).
- **cssLinkHref** `{String}` — optional per-template link href override (falls back to shared).

Pure-JS and pure-CSS builds pass no templates (`templates: []` or omitted). A token with
no `jsPath` throws. Duplicate resolved output names throw.

### 2. HTML outputs are a named map, not an ordered array + shorthands

The result's html surface is now **`result.html[name]`** — an object keyed by template
name, each entry `{ name, path, getHtml }`. The v3.5.0 `htmls[]` array and the
`getHtml()` / `htmlPath` shorthands are **removed**.

```js
const { html } = await build(outputDir, opts);
await html.default.getHtml();   // content of the "default" template
html.error.path;                // full path to the error template output
```

### 3. Per-template `cssPath` override

A template may supply its own `cssPath`, minified on demand (and not written as a
separate output file). The shared top-level `cssPath` remains the canonical output css
file (`result.cssPath` / `getCss()`).

## Migration from v3.x

```diff
 const result = await build(outputDir, {
   jsPath: '/…/component.js',
   cssPath: '/…/component.css',
-  htmlPath: '/…/index.html',
-  jsReplacement: '__JS_REPLACEMENT__'
+  templates: [
+    { name: 'index', htmlPath: '/…/index.html', token: '__JS_REPLACEMENT__' }
+  ]
 });

-await result.getHtml();
+await result.html.index.getHtml();
```

## Files changed vs v3.5.0

- `lib/index.js` — flat options removed (migration error); per-template `cssPath`/
  `cssLinkHref` resolution; minimum-input + token-without-jsPath validation ordering.
- `lib/build.js` — output getter exposes `html` map (removed `htmls[]`, `getHtml()`,
  `htmlPath`); added `minifyCssFile(cssPath, options)` for per-template css.
- `__tests__/test.spec.js` — specs build a single-element `templates` array; verify via
  `result.html[name]`; new migration/non-array/token-without-jsPath tests.
- `__tests__/integration.spec.js` — v4 API throughout; added per-entry `cssPath` test,
  non-array templates, and flat-option migration-error tests.
